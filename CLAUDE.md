# Launchpad

A pad where project ideas are assembled before you build them. Each idea is a rocket with six parts. A chat session with Claude, using the user's own API key, builds one part at a time. When all six parts are attached, the rocket launches into a `PLAN.md` and a kickoff prompt.

The GitHub repository is public. Security and stability come before the next feature.

npm workspaces, scope `@launchpad/*`, Node 24 (`.nvmrc`):

- `apps/api`: Express 5, Prisma 7 on Postgres 17, Better Auth, Zod 4, `@anthropic-ai/sdk`.
- `apps/web`: Next 16, React 19, plain CSS. This Next version has breaking changes. Read the guide in `node_modules/next/dist/docs/` before writing Next code.
- `packages/shared`: Zod schemas and types used by both. They are the contract between the web app and the API.

`apps/web/AGENTS.md` and `apps/web/CLAUDE.md` are generated by `next dev`. They stay untracked. Do not edit or stage them.

## Status

The three-day build runs from 2026-10-22 to 2026-10-24. `docs/SPRINTS.md` has the progress line and says which sprint is current. Read the current sprint's **Done when** before starting it.

## Commands

`npm run verify` and `npm run build` exist from Sprint 2a, `npm run dev` from Sprint 2b, and the database commands from Sprint 3.

- `npm run dev` runs shared, api and web together.
- `npm run db:up` starts the dev database. `npm run db:test:up` starts the test database.
- `npm run verify` is the local gate: public-repo check, typecheck, lint, format check, tests. Run it before saying work is done.
- `npm test` runs Vitest for all workspaces. From Sprint 3 it needs the test database.

## Where things are

- `docs/MASTER_PLAN.md` says what the product is and why: the screens, the data, the Claude integration, hosting.
- `docs/SPRINTS.md` sets the order of work and the **Done when** for each sprint.
- `docs/DEVELOPMENT_WORKFLOW.md` says how the work is done: reviews, commits, and the close-out routine.
- `LOG.md` is the build log.
- Rules live in `.claude/rules/`. The accessibility and web-ui rules load when you work under `apps/web`.

## Limits

- No OpenAPI spec for now. Zod schemas in `packages/shared` are the contract. Add the schema first, then a success test and a failure test, then the handler.
- Ask before adding any dependency, and say why an existing one will not do.
- Not built yet, and out of the three days: paid plans and a platform key, a light/dark toggle, Render hosting, offline mode. Ask before starting any of them.
- Tests mock the Anthropic SDK. No test and no CI run makes a network call.

## Build log

`LOG.md` has one numbered entry per piece of work. Each entry summarizes what I asked under **Asked**, in plain words and not word for word, and lists the results under **What came back / what changed**. Not every chat message needs an entry, and chats about my machine or tool settings stay out. The heading names the tool, such as Claude Code. The repository is public, so keep real tasks, private repositories, and personal details such as accounts, plans, emails, and local paths out of every file, including `LOG.md`, `CLAUDE.md`, and commit messages. Say what was fixed, not what is still open. See `.claude/rules/public-now.md`.

## Commits

I make every commit and every push. Agents review, stage, and suggest the message. Do not run `git commit` or `git push`, and do not open or merge a pull request.

At each sprint stop, follow `.claude/rules/ready-to-commit.md`. Do not start the next sprint until I say to continue.
